## 总体判断

保留现有白底、克制的蓝色、细线及对齐方式。下一版应让读者少做心算，优先建立信息之间的关系，而不是增加装饰。沿用 Apple 对布局对齐和图表视觉层级的指导：[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Charts](https://developer.apple.com/design/human-interface-guidelines/charts)。下面的具体改动是针对本产品的设计建议。

## 单条成绩

| 优先级 | 当前问题 | 建议 | 目的 |
|---|---|---|---|
| 高 | 等级 A 与星级、Mods 混在同一行；PP、Acc、Score、Combo 四列近似等权 | 把等级与 PP 关联；主指标保留 PP、准确率、最长连击，Score 降一级 | 首屏先回答这次成绩怎样 |
| 高 | 连击的分子分母同字号 | 使用“1,623× / 2,900×”，实际连击放大，分母缩小、灰色；只在数据确认时标记 FC | 清晰区分实际值与理论上限 |
| 高 | MISS 与 300/100/50 同权 | 把 Miss 靠近准确率或连击，保留文字及次数；非零时用少量暖色强调 | 第一眼找到失误 |
| 高 | FC / SS 估算远离当前 PP | 放到当前 PP 附近，使用“FC 估算”“SS 估算”；未来可加差值，但必须用同一算法的当前 PP 作为比较基线 | 减少跨区寻找和心算 |
| 中 | Aim / Speed / Acc 仅有数字 | 三条从零开始、使用同一数值尺度的横条，末端保留精确 PP；使用明确的“PP 分项”分组标题 | 更容易比较同一成绩的计算分项 |
| 中 | 谱面标题在图右上；下方可利用空间较多，而成绩在远下方 | 保留封面，将核心 PP 与成绩状态靠近谱面；缩短从谱面到成绩的阅读距离 | 建立“哪张图、什么成绩”的联系 |
| 中 | 星级和 Mods 使用同一种蓝色，彼此意义不同 | 星级保持中性色，蓝色优先用于主要 PP；Mods 固定为独立信息组 | 减少颜色争夺注意力 |
| 中 | BPM、CS、HP、OD、AR 在最细小的页脚 | 将实际参与比较的参数提升到谱面区域，低频信息留在页脚 | 避免数据存在却难以阅读 |
| 低 | 成绩时间使用 UTC，中文用户需要换算 | 使用明确的北京时间或允许指定时区，并保留时区标识 | 提高时间的直接可读性 |

Aim / Speed / Acc 是当前成绩的 PP 计算分项，不是玩家能力评分。横条只用于数值大小比较；不能用百分比堆叠到 API 总 PP，也不能把缺失分项显示为零。建议先使用横条；雷达图的轴刻度与面积解释会额外增加阅读成本，这里的主要目标是比较三个数值。

连击比不是游玩完成进度，不应做成“通关进度条”。Miss=0 也不保证 FC，仍可能有断滑等情况。未完成成绩要明确标记失败，不能从等级或连击比例猜测完成状态。

当前总 PP 优先使用 API，分项和 FC/SS 来自本地计算。对外显示差值前必须解决同源比较；暂不应直接用 FC 估算减 API PP 宣称可提高多少。PNG 无悬浮说明，来源区别应使用简短分组标题或可识别标签，不往图中放解释段落。

## BP 列表

推荐列顺序：序号 / 谱面与难度 / Mods / 准确率 / 连击与失误 / PP。日期放在谱面副行或最末的次要位置。

- 只在顶部放一次列标题，删除每行重复的 ACCURACY。
- Mods 固定列，防止长标题截断 Mods；NM 也应明确显示。
- 难度名与星级紧邻谱面标题。当前列表未提供星级，补充后需保证是对应模式及 Mods 的值；不能把原谱面星级冒充成绩星级。
- PP 保持右对齐，精度统一；加权 PP 和权重使用独立、清晰的次要标签。当前“95% · 571.37 pp”没有说明两者关系。
- 失误次数可以帮助区分“高 PP 但断连”和“完整发挥”的成绩。数据可得时再增加，保留未知状态。
- 封面缩略图属于低优先级，可选 48–64px 小图；不能牺牲难度名、Mods 或数字列宽。
- 长标题优先保留难度和 Mods：标题可省略，数值不能截断。20 条列表需按真实长标题、不同 Mods、低/高 PP、缺失权重再检查。

## 小尺寸与可读性

代码中的次要文字主要为 13–16px。1500px 图片缩到 800px 时，等效尺寸约为 6.9–8.5px；25px 分项数值约为 13.3px。此次浏览器截图中的标签、日期和页脚确实偏小。

按当前颜色计算：灰色 #6e6e73 对底色 #fafaf9 的对比度约 4.86:1；蓝色 #0066cc 约 5.33:1。这个结果只说明指定颜色的对比度，不能证明缩放后的整体可读性或无障碍合规。

建议把 800px 作为主验收尺寸，再检查 600px：核心标签约 22–24px（源图），主数值至少保持当前字号，删除重复标签来换取空间。若要求 600px 下仍能看清全部参数，应另做窄版模板；单纯缩放宽版很难兼顾数据量。

不要只用颜色区分 FC、失败和 Miss，始终同时保留文字。PNG 缺少可供辅助技术读取的文字层，若需要无障碍支持，应在调用方同时提供文字摘要或结构化成绩数据。

## 建议的第一轮实施范围

先修改 default 单条成绩模板：调整三项主指标与等级、分子分母层级、Miss 位置，关联 PP 估算，Aim / Speed / Acc 改为横条，统一关键标签字号。保留现有主题基调，不改 yaowan。

验收：

- 800px 宽时，玩家、谱面/难度/Mods、PP、Acc、连击及 Miss 能直接辨认。
- 3881559 的截图成绩明确显示 1,623× / 2,900×，分母权重低于实际连击。
- PP 分项使用统一尺度、数值准确，不显示未经定义的百分比或能力分。
- FC、0 Miss 但断连、失败、缺失 PP 和长标题的状态不被误导性呈现。
- 非 std 模式不出现 Aim / Speed / Acc，保留各模式判定。
- 低/高 PP、极长标题、无 Mods、多个 Mods、全球排名存在/缺失时均不重叠。

BP 列表作为第二轮，先解决列标题、Mods 与难度，再考虑缩略图和比较标记。
