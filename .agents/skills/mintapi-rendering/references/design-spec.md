# MintAPI 渲染设计规范 v1

本规范定义模板设计和后续优化的目标方向，不表示现有输出已全部符合。具体任务以用户当前要求和仓库 AGENTS.md 为准。

## 1. 设计目标

以聊天场景中的静态图片为主要输出，兼顾预览识别和原图阅读。

通过合理排版、明确层级和适当的信息密度提高空间利用率。保留现有字段和数据含义，不通过删除信息或持续缩小字号来简化布局。

## 2. 输出方向

**列表数据采用竖版，单项详情与分析报告优先采用横版。**

| 内容类型 | 输出方向 | 排版方式 |
|---|---|---|
| Recent、BP 等成绩列表 | 竖版 | 按行组织，结果列稳定对齐 |
| 排行榜、谱面搜索、谱面集难度列表 | 竖版 | 表格或紧凑条目，内容多时分页 |
| 多人历史、玩家排名等列表 | 竖版 | 按对局或玩家分组 |
| 单成绩、玩家信息、单谱面详情 | 横版 | 身份、核心结果、辅助信息横向组织 |
| 单局多人结果 | 依主体内容选择 | 玩家列表为主时竖版，单局摘要为主时横版 |
| PP 分析、BPM、局部难度等报告 | 横版 | 为图表提供充分宽度，内容多时分页 |
| Avatar card | 方形 | 头像与完整身份 |

横版详情不直接套用现有竖版布局，应重新安排区域比例。列表方向由主要内容决定，不由端点名称决定。

## 3. 信息层级

阅读顺序为：

1. **身份**：玩家、谱面、难度、模式和 Mods。
2. **核心结果**：PP、评级、准确率、排名等。
3. **支撑数据**：连击、判定、属性、分项与曲线。
4. **次要信息**：作者、ID、时间、分页和署名。

每张图片设置明确的视觉重点。通过字号、字重、位置和留白表达重要性，避免所有指标使用相同大小和强调程度。

## 4. 视觉风格

默认主题沿用浅色底、深色正文、灰色辅助文字、细分隔线和少量强调色。深色主题保留自身特点，共同遵循相同的信息层级和数据展示规则。

- 优先使用对齐、留白、表格和分隔线组织内容。
- 圆角主要用于头像、封面等适合的元素，避免堆叠同质卡片。
- 封面承担身份识别和氛围作用，其面积应服从信息布局。
- 渐变或遮罩用于保证封面上的文字可读，避免纯装饰性铺陈。
- 强调色表达重点、评级或状态；相同含义保持一致用色。
- 保留 osu! 的模式、Mods、评级和难度色谱辨识度。

### 背景融合与文字对比度

采用背景融合布局时，遵循以下原则：

- **背景融入身份区**：谱面背景可作为头部底图，与玩家、谱面信息组成一个完整区域，减少独立封面占用。根据图片主体和文字位置安排裁切，保留谱面的辨识度。
- **边缘柔和过渡**：局部背景图通过透明度渐变消除矩形边缘，并自然过渡到正文底色。图片边界的融合与文字区域的对比度分别处理。
- **区域统一调整对比度**：同一区域优先使用整体遮罩或渐变保证文字清晰，避免每段文字分别叠加白色底块。文字颜色和字重应配合遮罩后的实际背景选择。
- **避免局部模糊光晕**：白色模糊底在深色或复杂背景中容易产生脏灰感。需要提亮时，优先调整头部上沿或文字所在的完整区域，避免标签周围出现孤立的亮斑。
- **背景止于身份区**：核心成绩和明细保持纯色底，保证数值、判定和图表的稳定对比度。

具体画布尺寸、图片宽度、渐变比例和透明度属于模板实现细节，应根据实际内容和渲染结果调整，不固化为所有模板共用的参数。

## 5. 字体与数据格式

优先复用本地 HarmonyOS Sans SC 和现有字体回退方案，建立稳定的标题、主数值、正文、辅助信息四级字号。

- 核心结果在聊天预览中应易于辨认。
- 同类数字采用等宽数字，并保持统一对齐。
- 表格数字右对齐；单位靠近数值，但降低视觉权重。
- 精度按字段语义统一，避免同类数值格式不一致。
- 图标复用现有资源，控制大小和数量，避免压缩正文空间。
- 缺失数据显示 `—`、未知或明确空状态，不能填成零。

## 6. 空间利用与长内容

优先调整布局、区域比例和分页，再决定字号。

- 合并相关信息，减少重复标题、大图标和无意义固定留白。
- 有条件显示的区域应在缺失时释放空间。
- 详情中的长名称和标题优先换行，必要时扩展对应区域。
- 密集列表允许明确省略，但保留关键身份和结果。
- 为大数值、多 Mods、多徽章和不同模式预留适配策略。
- 内容超过合理容量时分页，避免无限加长或把全部文字缩小。
- 画布尺寸与渲染参数保持一致，不产生裁切、横向溢出或重叠。

## 7. 单成绩横版布局

`/recent_play` 单成绩作为第一批优化样板，其他单成绩输出复用共同规则。

- **头部身份区**：玩家身份、模式和成绩类型放在顶部一行；谱面标题、作者、难度、星级和 Mods 形成连续的信息组。谱面背景可融入头部，按背景融合原则保证文字清晰。
- **核心结果区**：PP、评级、准确率、连击和 Miss 集中一行展示，形成明确主次；大数值需要换行时只扩展对应区域。
- **明细区**：判定与 PP 分析并排，按四模式调整判定列数。PP 分项、FC/SS 预测按相关性组织；没有分项的模式重新分配空间，避免留下空白占位。
- **底部元数据区**：集中排列时间、谱面属性、ID、排名等完整信息，署名单独预留位置。
- 普通成绩保持紧凑；长名称、长标题或多 Mods 自然换行并扩展受影响区域，不以固定高度裁切内容。

## 8. 图表与列表

图表明确标题、坐标轴、单位和图例。重要结果直接标注，不能依赖悬停才能理解。

同一种数据跨图保持一致颜色。历史缺口不连接成虚假连续记录，不伪造零值；局部 strain、累计难度和星级分别按真实含义标注。

列表保持行结构、封面比例、数字列和字段位置稳定。强调重点条目时控制范围，保证整页易于扫读和比较。

## 9. 实现与署名

数据计算、资源准备和格式化放在服务或主题模型中，HTML/CSS 负责展示。外部文本插入 HTML 前必须转义。

复用现有 Chromium PNG 渲染流程，等待字体和图片就绪后确定尺寸并截图。

默认输出沿用统一的 MintAPI 署名和北京时间绘制日期，为其预留空间；已有非默认主题按现行约定处理。

**Avatar card 直接渲染，不添加水印、MintAPI 署名或绘制日期。**

## 10. 验收标准

使用真实渲染流程生成图片，并检查原图和聊天预览两种阅读尺寸。

验收覆盖普通数据、长中英文名称、长难度名、大数值、缺失字段、可变条目数，以及相关的四模式差异。

采用背景融合布局时，还应覆盖亮色、暗色、高对比度和复杂纹理背景，检查图片边界、过渡接缝、文字对比度和主体裁切。特别检查右上角等靠近图片主体的文字区域，避免局部底块或模糊光晕产生脏灰感。

优化前后使用相同数据对照，确认：

- 信息完整、含义准确。
- 身份与核心结果更容易识别。
- 空间分配合理，辅助信息仍可阅读。
- 字体、图片、图表和署名正常。
- 无裁切、重叠、横向溢出或异常留白。

构建成功和 HTML 断言作为辅助验证，真实图片检查作为视觉验收。
